# 娃醒了 v2.0 · 睡眠会话方案（入睡 / 夜醒次数 / 彻底清醒）

状态：已实施（v2.0.0，2026-10-25；定稿为 r2 单击模型——**不设「接着睡了」**，半夜操作与 v1 相同）

## 1. 目标与设计原则

目标：

- 记录**入睡时刻**（什么时候睡着）
- 记录**夜醒次数**（点几下就是几次，与 v1 完全一样）
- 记录**彻底清醒时刻**（起床）
- 一夜自动汇总：入睡 → 起床、整夜时长、各觉时长、最长一觉

**半夜操作不比 v1 多一下**——这是本方案的第一原则。醒来仍然只点一下「醒了」；新增的两次点击（「睡着了」「起床」）都发生在父母清醒的睡前和早晨。哄睡完那一下不加，累的时候少一步是一步。

明确不做：**每次醒着多久（哄睡耗时）**。它要求哄睡成功后再点一次手机，违背第一原则；且儿医沟通、妈妈复盘用得最多的是"次数"和"各觉时长"，不是哄睡耗时。

## 2. 核心转变：离散醒点 → 睡眠会话

现状（v1）：每条 `WakeRecord { id, ts }` 独立成条，属于哪一夜靠时间规则**逐条推断**（`nightDate`）。

新版：**一夜 = 一个 `SleepSession` 对象**。入睡时刻、醒点数组、起床时刻都是这一夜的字段。

收益不变：**归夜判定只在"开新夜"时发生一次**。之后哪怕早上 7:40 才记"起床"，也明确挂在昨夜会话上——07:00 不再是硬边界；跨月夜（23:50→00:10）的跨桶问题也消失。

## 3. 数据模型与存储（common/store.uts）

```uts
// WakeRecord 复用 v1 类型，不改动：{ id: string, ts: number }

export type SleepSession = {
  id: string,                 // 's' + night（一夜一会话）
  night: string,              // yyyy-MM-dd 夜归属键（= 入睡那天日期）
  bedtime: number,            // 入睡时刻；0 = 未记录（夜里直接点"醒了"自动开夜）
  wakes: Array<WakeRecord>,   // 醒点数组，就是 v1 的记录
  wakeUp: number              // 彻底清醒时刻；0 = 进行中 / 未记录
}
```

相比 r1 删除了 `WakeEvent.end`（"接着睡了"补的时刻），模型退化为"v1 记录数组 + 首尾两个时刻"，迁移因此更简单。

存储延续按月分桶，只换桶前缀与索引：

- 桶 key：`wa_sessions_YYYYMM`（按 night 所在月）
- 月份索引：`wa_session_months`
- 版本标记：`wa_schema = 2`

### 一次性迁移（App.uvue onLaunch）

1. 读 `wa_schema`；若 ≠ 2 且存在旧 `wa_months`：按旧 `nightDate` 规则把 `wa_records_*` 逐条分组
2. 每夜合成 `SleepSession`：`bedtime = 0`、`wakeUp = 0`、`wakes` 原样搬入
3. 写入新桶并设 `wa_schema = 2`；**旧 key 原样保留不删**（可回滚、可排查）
4. 迁移后所有读写只走新结构

历史页兼容：`bedtime = 0` 的夜显示「未记入睡」，卡片标注**旧版数据**。

## 4. 一夜的状态机与记录页交互

```
IDLE ──睡着了──▶ SLEEPING ──醒了(单击×N)──▶ ──起床──▶ DONE
 │                │
 └─(夜里直接点"醒了"：自动开夜，bedtime=0)
```

只有三个状态，主按钮文案：

| 状态 | 主按钮 | 副文案 | 次按钮 |
|---|---|---|---|
| IDLE（白天 / 晚上未开夜） | 睡着了 | 娃闭眼睡下就点 | — |
| SLEEPING | 醒了 | 点一下 · 记一次 | 起床 |
| DONE | 今晚已结束（置灰） | 晚上 8 点开始新的一夜 | — |

顶部统计区：

- SLEEPING：大数字「今晚已醒 N 次」+ 副行「入睡 21:32 · 这一觉已 2h05m」（自上次事件起算，妈妈最关心的"现在这觉睡了多久"免费得到）
- DONE：大数字换成「9h55m」整夜时长，副行「入睡 21:32 → 起床 07:02 · 醒 2 次」

### 关键决策

1. **忘记点"睡着了"**：夜间窗口直接点"醒了" → 自动以该时刻开夜，`bedtime = 0`。历史标"未记入睡"。老用户习惯（打开就点大按钮）完全兼容。
2. **醒着多久不记录**：见 §1 第一原则。替代数据是各觉时长（间隔），自动可得。
3. **起床晚于 7 点**：无影响，挂在会话上。
4. **"起床"点早了**：5 秒撤销窗口兜底；错过就等 P1 的时间编辑修正。
5. **回笼觉不记**：点完"起床"当天按钮置灰等晚上，口径干净（一夜一次首尾）。真想补，同样走 P1 编辑。
6. **撤销**：沿用"最近一步可撤销、5 秒窗口"，动作三类（记入睡 / 记醒 / 记起床）。撤销"醒了"时若该夜因此变空且 `bedtime = 0`，连带删除空会话。
7. **白天点按钮**：07:00–19:59 且无进行中会话 → 主按钮置灰，文案「晚上 8 点开始记今晚」。

### 开新夜判定（time.uts 扩展）

- 进行中会话 = 最近一个 `wakeUp == 0` 的 session
- 无进行中会话且 `isNightTime(now)` → IDLE（今晚未开始）
- 点"睡着了"且 `isNightTime(now)` → 开新夜，`night = nightDate(now)`（凌晨 0–7 点开夜由现有规则自动归前夜）
- 新增会话状态判定纯函数供记录页消费，UI 不做时间判断

## 5. 历史页

胶囊（两枚，维持 v4 精简版式）：

- 高亮：「昨晚醒 2 次 · 整夜 9h55m」
- 次要：「近 7 天 18 次」

卡片头部一眼看全夜：

```
10月24日 · 周五                 醒了 2 次 ▾
21:15 → 07:10 · 整夜 9h55m
```

展开内容：

- **夜间时间轴**（20:00–08:00）：蓝条 = 睡、**黄点 = 醒（点标记，不画段）**、灰 = 未记录
- 明细行（右侧展示"这一觉"时长，即相邻事件间隔）：
  - `21:15 入睡`
  - `02:24 醒了 · 这一觉 5h09m`
  - `05:03 醒了 · 这一觉 2h39m`
  - `07:10 起床 · 这一觉 2h07m`
  - 醒点保留删除 ×；**最长一觉**在明细底部高亮一行（免费数据）
- 旧版夜：无时间轴、无首尾行，明细只有醒点，卡片标注「旧版数据 · 未记入睡/起床」

## 6. 统计口径

- **夜醒次数** = `wakes.length`，与 v1 完全一致，历史趋势可比
- **整夜时长** = `wakeUp − bedtime`（两者都非 0 才计算）
- **各觉时长** = 相邻事件间隔：bedtime→首醒、醒ᵢ→醒ᵢ₊₁、末醒→wakeUp
- **最长一觉** = 各觉时长的最大值
- 不统计、不估算：醒着合计、"净睡时长"（数据不存在，不编数）

## 7. 每晨通知（uni_modules/wa-notify）

- JS 接口：`setSummary(key, count)` → `setSummary(key, count, spanText)`，`spanText` 为 `9h55m` 或空串
- 原生端 SharedPreferences 增存一个 string；receiver 拼 09:00 文案：「昨晚醒 2 次 · 整夜 9h55m」；`spanText` 为空退回「昨晚醒 2 次」

## 8. 边角 case 一览

| 场景 | 行为 |
|---|---|
| 夜里忘了开夜，直接点"醒了" | 自动开夜，`bedtime = 0` |
| 忘点"起床"就过去了 | 昨夜 `wakeUp = 0`，历史标"未记起床"；次日照常开新夜 |
| 起床在 7 点后 | 挂会话，无影响 |
| "起床"点早了 | 5 秒内撤销；错过走 P1 编辑 |
| 回笼觉 | 不记，当天置灰；需要时 P1 编辑补 |
| 白天想记录 | 置灰 + 引导文案 |
| 跨月夜（23:50 醒 → 00:10 醒） | 会话整体存 night 当月桶 |
| 旧数据 | 启动一次性迁移，卡片标「旧版数据」，旧 key 保留 |
